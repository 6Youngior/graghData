# 阈值支配实验协议

## 目的与控制

检验预算相关的边界支配是否保持答案精确、减少实际查询工作，以及收益在什么结构和代价下出现。主比较固定相同 Hybrid 编码与同一答案核，仅改变边界；CSR 求交另作对应的剪枝前后比较。

数据：SNAP Wiki-Vote、p2p-Gnutella31、email-EuAll。输入 SHA-256 见 data/source_manifest.json，清理计数见 data/processed/*.json。删除自环/重复边，保留有向环、方向和原始 ID，不作 SCC 缩点。Email 去 1089 自环后 418956 边。

主覆盖为打乱边顺序、种子 17 的极大匹配端点，逐边验证覆盖。k=2/4/6 分别编码、分别建立两种预算边界；主结果固定 k=4。

## 查询和真值

复用 data/results/kreach 中已保存的完整 BFS 真值。每图/k/分布/查询种子 5000 条，种子 17/29/43，实际生成器种子 seed+100k。

uniform 在非零出度源与非零入度终点之间均匀抽样，排除同点；并非全节点含悬空端点的均匀。balanced 严格正负各半，正例 d≤k，负例 d>k 或不可达，按完整 BFS 分类。二者都是受控人工分布，不冒充生产日志。布局和支配只依赖图及 k，没有训练、调参或测试集选择。

54 个查询批次，270000 查询条次；相同查询比较八方案，432 配置、2160000 次判定。与方法次数区分，不能称作 216 万独立点对。

## 八方案

1. Ranked-CSR：原边界预先转为核心 ID，有序目标表与两位码。
2. Join-CSR：原文 §4.2.2 有序表求交，按确定成本在逐点二分与求交间切换。
3. Dominance-CSR：双侧支配剪枝，CSR 逐点查询。
4. DominanceJoin-CSR：相同求交逻辑，改为剪枝边界。
5. Ranked-Adaptive：原边界，相同 Hybrid 核心编码。
6. Dominance-Adaptive：双侧边界约简，其余与 5 相同。
7. Source-Adaptive：仅约简出边界。
8. Target-Adaptive：仅约简入边界。

原边界也预先转核心 ID，控制 ID 转换成本。求交基线有助于避免只比较较弱逐点路径；仍不冒充作者全部优化的 C++ 实现。

## 计时与统计

固定逻辑核 2，Numba 单线程、预热后的答案核；每配置九次，轮内打乱方法顺序。每次先估计批耗时，再重复约 80ms，取中位数。包含答案数组分配，排除首次 JIT、构建和诊断。主实验原始计时 3888 条。

报告热态批吞吐折算 μs/query，不是单请求 RPC 延迟。加速比先在同批配对后计算：主图每点是三个种子的算术平均、横线是范围；汇总表是两分布三种子配对比的几何平均。横线不是置信区间，不把接近 1 的波动解释为收益。

point_path_probes 统计逐点路径下的核心查找。求交方案的该诊断用于逻辑对照，不声称等于实际 merge 扫描次数；计时走真实求交分支。主机制图只比较相同 Hybrid 的逐点路径。

## 构建与空间

每图共享一次到 kmax=6 的核心截断距离暂存，供三个 k 编码。支配构建时间单独测量，在小图预热后记录。原型同时生成两预算/两方向证书，发布部署时可以释放。

部署字节计入核心索引、cover/rank 及实际唯一边界数组。原边界两预算共享数组，不能重复计数；剪枝后的列表分别保存。原图 CSR、原 SNAP ID 映射、查询数组和 Python 对象开销另属公共输入，不在索引列。ZIP / NPZ 压缩大小不代替驻内存。

构建距离暂存和额外位集合证书单列，不冒充最终索引或峰值 RSS。以全部剪枝边界构建成本保守估计 Wiki 分摊点；不宣称本次小批查询就取得端到端收益。

## 验证、稳健性与压力测试

- 124 小图全部点对，含三点全部有向图；与独立 Python deque BFS 对照，包含原/单侧/双侧和 CSR 求交。
- 所有新答案逐条对照保存的完整 BFS 真值。该真值另已有 SciPy 648 条最短距离抽查。
- 对真实图全部被消去边界，用直接整数距离验证存在保留代表，独立于构建位集合。
- 原边界逐条探测数与原基本 K-Reach 实现一致；显式统计实际查找增加的查询，不只报告下降平均值。
- 覆盖种子 29、43：三图 k=4、查询种子 17、两分布，另存 dominance_cover，不与主实验混算。补充 60,000 查询条次 / 480,000 次判定。
- 保留全部四类端点及候选积 1 / 2–4 / 5–16 / ≥17 的结构分层，不只保留最快子集。
- 合成图仅为机制压力测试：嵌套边界、d=4/8/16/32/64、32×32 点对、正负两类，九次打乱顺序计时，约 40ms。逐点次数严格核对解析式 d² 或 d(d−1)+1，剪枝后为 1。它不进入真实图主统计，不作业务加速宣传。
- 原文图和增边课程反例分别保存；全部点对/k 的 Python/JS 夹具和离线浏览器检查均复核。
